# 平台能力与接入边界

xcss 的当前版本见根 README；包、运行形态和能力定义共同描述发布接口。
产品是否通过验收由当前清单、锁文件、同一源码的独立构建、实际 CI 和正式发行决定，不能由上游测试结果代替。

## 依赖方向

xcss 不依赖产品 crate，不按 `product_id` 分支，不提供产品名 Feature。
运行形态通过运行形态表达，公共差异通过能力和 Adapter/Trait 表达；
产品数据结构、业务协议和业务生命周期由消费者拥有。
`scripts/check-xcss.py` 检查 Rust/npm 内部依赖身份、各声明作用域和仓库外本地路径。

## 公共能力

- Rust：管理员认证、当前 Schema 身份、SQLite、状态文件、运行时生命周期、文件系统安全、秘密封装、有限 HTTP 请求及操作状态机。
- Web：管理员客户端、React Shell、原生 ESM 适配、UI、设计令牌、字体和构建工具链。
- 工具：结构组合工具、源码与发行一致性检查、产品无关 Testkit 和消费者报告。

## 接入验收

每项公共能力需要明确规范、当前合同、产品无关测试、xcss 实现和实际消费者适配器。
消费者固定完整不可变修订号或发行包，并独立构建和运行其业务测试；未完成接入的能力应如实记录状态。
产品业务验证保留在产品仓库，xcss 不以读取下游源码或私有测试夹具作为构建前提。
