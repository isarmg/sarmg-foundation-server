# 改动工作流

## 确定职责

从实际产品调用点说明要共享的机制、输入输出、状态所有者和产品仍需完成的业务。通用机制可由 xcss 独立测试，产品特有的协议、数据与动作由适配器提供。消费者数量不作为机械门槛。

## 实现并验证

1. 修改公共 API 和相邻测试。
2. 涉及跨语言数据时同步 Rust、TypeScript guard、JSON Schema 与共用夹具。
3. 涉及状态或副作用时验证错误、预算、取消、并发与中断恢复的相关路径。
4. 按[构建与测试](development.md)运行受影响模块和完整检查。
5. 在实际消费者中接入，保留其业务规则和测试。

专题场景见[测试参考](reference/testing.md)。认证、运行时、数据库和 Web 的调用细节从[参考索引](reference/README.md)定位。

## 发布并更新消费者

先用本地联调验证 API，再生成新的不可变版本。产品改用完整 Git revision 和发行 tgz URL，更新锁文件，在没有相邻 xcss 源码的独立检出中构建和验收。

公共库修复需要消费者重建、测试和重新发布后才进入生产。记录实际源码、CI、发行资产与未执行的平台或产品场景。发行工具和下载复核见[操作说明](operations.md)。

## 删除或替换能力

先从实际依赖图和调用点确定影响，同步产品调用、测试、导出和文档，再检查构建输出与真实归档是否仍含旧文件。持久状态变化按产品实际数据合同处理，公共库的格式规则见[当前格式决策](architecture/ADR-0010-current-format-and-maintenance.md)。
